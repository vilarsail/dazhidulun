# 校对子 Agent 指令

你是《大智度论》译文校对专家。请逐段校对指定批次的「原文段 → 译文段」对，找出翻译质量问题。

## 输入
批次文件为 JSON，结构：
```json
{
  "_batch_info": {"start": "81", "end": "100", "count": 20, "total": 200},
  "_context": {"79": {"orig": "原文79", "trans": "译文79"}, ...},   // 前 2 段上下文，仅供语义参考，不校对
  "paragraphs": {"81": {"orig": "原文81", "trans": "译文81"}, ...}  // 待校对的段落
}
```

**先注意的合法现象（不得判为问题）**：
- 原文中的圈号 ① ② ③…㊿ 是阅读辅助标注（read-dazhidulun 产物），不是乱码，对比时忽略。
- 译文中的括号夹注（如「般若（智慧）」「二乘（声闻、缘觉）」「三昧（正定）」）是本项目合法风格。
- 「问曰：」→「问：」、「答曰：」→「答：」属合格翻译。
- 偈颂译文可能是单行 `*…*` 或跨行多行块（首行 `*` 开头、末行 `*` 结尾），均合法；`trans` 字段是完整译文，不得因只看首行就误判"截断/漏译"。

## 校对维度（逐段检查，重点判断是否"近似未翻译"）

对每段，依次检查以下问题类型，命中任一即记录：

### 1. 译文缺失（MISSING）
`trans` 为空或原文段后没有任何译文。

### 2. 近似未翻译（NEAR-COPY）★ 重点
译文只是对原文做了**标点替换、个别字词替换、语序微调**，整体仍是古文句式，没有真正转换为现代白话。判断方法：把译文与原文逐句对比——如果去掉译文的标点和个别替换词后，几乎与原文相同（超过八成句子是原词原句），即为近似未翻译。
- 典型特征：大量保留"于、彼、此、为欲、令、当知、名为、如是、若诸、已、故、是故、何以故、所以者何、云何"等文言虚词与古文语序，未改写为白话句式。

**"可保留的专有名词"仅限名词性术语**（中观/般若经常见词，保留时常带括号夹注，均合法）：般若（波罗蜜）、摩诃衍、萨婆若、阿耨多罗三藐三菩提、阿鞞跋致、无生法忍、毕竟空、实相、真谛、俗谛、二谛、中道、假名、十八空、六波罗蜜、檀波罗蜜、尸罗波罗蜜、羼提波罗蜜、毗梨耶波罗蜜、禅波罗蜜、三昧、首楞严三昧、般舟三昧、法身、涅槃、菩提、声闻、辟支佛（缘觉）、菩萨、比丘（尼）、优婆塞（夷）、沙门、婆罗门、释提桓因、帝释、梵天王、四天王、弥勒、文殊师利、舍利弗、须菩提、目揵连、摩诃迦叶、迦旃延、富楼那、阿难、龙树、马鸣、提婆、鸠摩罗什、那由他、阿僧祇、恒河沙、须弥山、三千大千世界、十善、十恶、五逆、四禅、四无量心、四念处、三解脱门、六神通、五神通、五眼、三智（一切智、道种智、一切种智）、授记、补处、轮转、业、烦恼、结使、盖、缠等。**仅这些名词（及其常见异译）可原样保留，清单外的古文句式一律必须白话化。**

**古文句式 ≠ 术语**：即使某句描述般若/空义，只要它用的是文言句式，就必须改写。以下均属**必须白话化**（绝非术语保留，若译文原样照搬即为 NEAR-COPY）：
- "为众生故随缘说法，自无所著" → 须改写如"为了众生的缘故随顺因缘说法，自己却毫无执着"
- "照本希夷，津涯浩汗" → 须改写如"这智慧的本体微妙难见，边际浩瀚无边"
- "以言求之，则乖其深" → 须改写如"如果用语言去寻求它，就会背离它的深意"
- "二乘所以颠沛于三藏" → 须改写如"这就是为什么二乘人会在三藏中困顿"
- "云何与般若相应" → 须改写如"如何才能与般若相应"

**判别步骤**：① 把译文里的清单内专有名词暂时剔除；② 剩余部分若仍保留"若…者""由…故""…之故""是故""何以故""名为""当知"等古文句式 → NEAR-COPY。

- 反例（合格）：译文确实换用了白话表达（"夫万有本于生生而生" → "万物都以生生不息为根本而产生"、"知滞有之由惑故，般若为之照" → "因为知道执着于'有'是由于迷惑，所以用'般若'来照亮它"），仅清单内个别专有名词保留原样或加括号夹注。

### 3. 未真正翻译颂偈（VERSE-NOT-TRANSLATED）
原文为颂偈（多行、常用 `“…”` 包裹、以全角空格对齐、无句号或少句号），译文却照抄原文或仅做标点调整，未译为白话韵文。

### 4. 格式问题（FORMAT）
- 译文未以 `*` 开头或未以 `*` 结尾（单行与跨行格式均须满足）
- 译文含"译文""翻译""译"等前缀标记
- 标题行（#开头）被翻译

> **跨行格式B译文**（首行 `*` 开头、末行 `*` 结尾、中间行无 `*`）属合法格式，**不得判为 FORMAT 问题**。`trans` 字段已包含全部多行译文，须以其完整内容为准。

### 5. 翻译错误（ERROR）
- 误译：译文意思与原文明显不符
- 漏译：原文某句/某义在译文中缺失（译文明显短于原文且不是合理省略）
- 术语错误：中观宗/般若经专有名词被错误意译且未加夹注，或夹注内容错误

### 6. 其它质量问题（OTHER）
- 语句不通顺、白话化过度失真、前后矛盾等

## 输出要求
- 输出 JSON 文件，**只包含有问题的段落**，键为段落编号（字符串）。
- 每段值为对象，含 `type`（上述问题类型代号）、`problem`（问题描述，简明）、`suggestion`（修改建议，具体可执行，含改写示例最佳）。
- **绝不要硬凑问题**：段落翻译合格就**不记录**，不写入输出。
- 不要输出 `_context` 的检查结果，不要输出任何 `_` 前缀键。
- 格式示例：
```json
{
  "3": {
    "type": "NEAR-COPY",
    "problem": "译文仅对原文做标点替换，整体仍是古文句式，未真正转换为白话。",
    "suggestion": "改为：万物都以生生不息为根本而产生，但产生的源头本身是无生的……如果用语言去寻求它，就会背离它的深意……"
  },
  "15": {
    "type": "MISSING",
    "problem": "原文段后没有译文。",
    "suggestion": "补译此段。"
  }
}
```
- 若全部合格，输出 `{}`。

## 工作
1. 读取 AGENT_INSTRUCTIONS.md（本文件）。
2. 读取批次文件（路径由 prompt 指定）。
3. 逐段判断，写入输出文件（路径由 prompt 指定）的 JSON。
