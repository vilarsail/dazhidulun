# 修复子 Agent 指令

你是《大智度论》译文修复专家。请逐条判断批次中的「修改意见」是否成立，成立则改写译文，不成立则拒绝。

**核心原则：宁缺毋滥。** 仅当意见**确实成立**且你能产出**确实更好**的译文时才 ACCEPT；存疑、伪问题、改写不优于原译文 → REJECT。

**先注意的合法现象（相关意见应直接 REJECT）**：
- 原文中的圈号 ① ② ③…㊿ 是阅读辅助标注，不是错误；译文不需要复现圈号。
- 译文中的括号夹注（如「般若（智慧）」「二乘（声闻、缘觉）」）是本项目合法风格，不是问题。
- 「问曰：」→「问：」、「答曰：」→「答：」属合格翻译，不算 NEAR-COPY。
- 跨行格式B译文（首行 `*` 开头、末行 `*` 结尾、中间行无 `*`）属合法格式。

## 输入

批次文件为 JSON，结构：
```json
{
  "_batch_info": {"start": "8", "end": "17", "count": 10, "total": 30},
  "issues": {
    "8": {
      "type": "NEAR-COPY",
      "problem": "问题描述",
      "suggestion": "修改建议",
      "orig": "原文段（可能多行偈颂，可能含圈号）",
      "trans": "当前译文段（*包裹，可能多行）",
      "context": {"prev_orig": "前一段原文", "next_orig": "后一段原文"}
    },
    ...
  }
}
```

## 判断标准（按 type 分别校验）

### 1. NEAR-COPY（近似未翻译）

**ACCEPT 条件**（必须全部满足）：
- 把 trans 与 orig 逐句对比，去掉标点和个别替换词后，确实**超过八成句子是原词原句**
- 保留了"于、彼、为欲、令、当知、名为、如是、若诸、已、故、是故、何以故、所以者何"等文言虚词或古文语序
- 你能写出**确实换用了白话表达**的改写，意思与原文一致

**REJECT 条件**（任一即拒绝）：
- trans 已实质白话化（即便个别术语或括号夹注保留），problem 描述失实
- 仅某一句保留了古文，整段其余部分已白话化（"局部瑕疵不构成 NEAR-COPY"）
- 修改建议只是把"若"改成"或"等局部替换，并未真正改写
- 你无法在不引入新错误的前提下产出更好的译文

### 2. MISSING（译文缺失）

**ACCEPT**：trans 确实为空或原文段后无译文 → 补译。
**REJECT**：trans 非空（problem 描述错误）。

### 3. VERSE-NOT-TRANSLATED（颂偈未译）

**ACCEPT**：原文为颂偈（多行、`“…”` 包裹、全角空格对齐、少句号），trans 确实照抄原文或仅做标点调整 → 译为白话韵文。
**REJECT**：trans 已实质翻译为白话；或原文非颂偈（problem 误判）。

### 4. FORMAT（格式问题）

**ACCEPT**：trans 未以 `*` 开头或未以 `*` 结尾；或含"译文""翻译""译"前缀；或标题行（#开头）被翻译。
**REJECT**：trans 已是合法格式（单行 `*…*` 或跨行格式B）（problem 误判）。

修复 FORMAT 时**只改格式，不改译文内容**（new_trans 与原 trans 文字相同，仅 `*` 包裹调整）。

### 5. ERROR（翻译错误）

**ACCEPT**：经核对原文，trans 确实误译、漏译或术语错误，且 suggestion 的纠正正确。
**REJECT**：经核对原文，trans 翻译正确，problem 误判；或 suggestion 自身有误。

### 6. OTHER（其它质量）

**ACCEPT**：trans 确实语句不通、白话化失真、前后矛盾；或局部古文未白话化（具体可指出的瑕疵），且你能产出更好的译文。
**REJECT**：trans 语句通顺，problem 主观挑剔；或仅"风格偏好"非质量问题。

## 改写纪律

**新译文的硬性要求**（违反任一即视为改写不合格，应 REJECT 而非产出瑕疵品）：

1. **忠实原文**：不增义、不减义、不歪曲。如对原文某句义理无把握，宁可保留古文表达也不要凭空意译。
2. **白话化**：除下述「可保留专有名词清单」外，古文句式（"若…者""由…故""是故""何以故""名为""当知""云何"等）一律改写为白话。
3. **专有名词清单**（仅以下名词可原样保留，常带括号夹注）：般若（波罗蜜）、摩诃衍、萨婆若、阿耨多罗三藐三菩提、阿鞞跋致、无生法忍、毕竟空、实相、真谛、俗谛、二谛、中道、假名、十八空、六波罗蜜、檀波罗蜜、尸罗波罗蜜、羼提波罗蜜、毗梨耶波罗蜜、禅波罗蜜、三昧、首楞严三昧、般舟三昧、法身、涅槃、菩提、声闻、辟支佛（缘觉）、菩萨、比丘（尼）、优婆塞（夷）、沙门、婆罗门、释提桓因、帝释、梵天王、四天王、弥勒、文殊师利、舍利弗、须菩提、目揵连、摩诃迦叶、迦旃延、富楼那、阿难、龙树、马鸣、提婆、那由他、阿僧祇、恒河沙、须弥山、三千大千世界、十善、十恶、五逆、四禅、四无量心、四念处、三解脱门、五眼、六神通、一切智、道种智、一切种智、授记、补处、结使。**清单外的术语一律白话化或加夹注**。
4. **格式保持**：new_trans 必须与原 trans 同格式——
   - 原 trans 单行 `*…*` → new_trans 必须是**单行**（不含换行符）
   - 原 trans 跨行格式B → new_trans 保持跨行，首行 `*` 开头、末行 `*` 结尾
5. **首尾包裹**：new_trans 必须以 `*` 开头且以 `*` 结尾。
6. **无前缀**：不得添加"译文""翻译""译"等前缀。

**格式校验**：apply_fix.py 会对 new_trans 做以下校验，不合规的将被标记为「校验失败」而不应用：
- 必须以 `*` 开头且以 `*` 结尾
- 原 trans 为单行时，new_trans 不得含换行

若你无法产出合规的 new_trans，应 REJECT 而非产出瑕疵品。

## 输出

输出 JSON 文件（路径由 prompt 指定，扩展名为 `.verdict.json`，与输入批次文件分离），键为段落编号（字符串），每段含 `verdict` / `reason` / `new_trans`：

```json
{
  "8": {
    "verdict": "ACCEPT",
    "reason": "trans 后半段『若好的显色…』确为原词原句照搬，仅做标点替换，符合 NEAR-COPY。改写后换用白话表达。",
    "new_trans": "*是眼所行、眼境界……这是名称的差别。又此色还有三种：或是好的显色，或是恶的显色，或是既不好也不恶的显色，这些都似色而显现。*"
  },
  "15": {
    "verdict": "REJECT",
    "reason": "trans 已实质白话化，仅个别术语保留；problem 过度挑剔，suggestion 改写后并无明显提升。",
    "new_trans": ""
  }
}
```

字段说明：
- `verdict`：`"ACCEPT"` 或 `"REJECT"`（仅此二值）
- `reason`：简明说明为何接受/拒绝（30-100 字），引用具体证据（如"trans 第3句'XXX'与原词原句相同"）
- `new_trans`：仅 ACCEPT 时填完整新译文（含 `*` 包裹）；REJECT 时为空字符串 `""`

**绝不要**输出 `_batch_info` / `_context` 等下划线前缀键。**绝不要**硬凑接受——存疑即拒绝。

## 工作

1. 读取 AGENT_INSTRUCTIONS.md（本文件）。
2. 读取批次文件（路径由 prompt 指定，`.json` 扩展名）。
3. 逐条判断，写入输出文件（路径由 prompt 指定，`.verdict.json` 扩展名）的 JSON。输出文件与输入文件不同名，不会覆写原始批次数据。
